Features

  • VGA 640×480@59.94, R4G4B4 (12-bit) color throughout
  • Fixed-rate indexed pixel stream + beam-locked RLE command stream
  • Pixel-exact mid-line register writes (SET, banked-pair law)
  • Per-line palettes at zero slot cost (hblank-eager SETs)
  • Micro-HAM 2bpp mode for high-fidelity still images
  • No CPU bus on PIXEL / TIMING / COMPOSITOR — all state in-band

Device Complement

  • ENGINE — ATF1508AS, descriptor DMA master (123/128 LC)
  • PIXEL — ATF1508AS, stream unpacker (122/128 LC)
  • COMPOSITOR — ATF1508AS, VIDCMD playback (112/128 LC)
  • TIMING — ATF1504AS PLCC44, raster + syncs (31/64 LC)
  • 2×2 IDT7200L15 FIFOs (256×9): PIXELS and VIDCMD streams
  • 2× 74AC541 + R4G4B4 ladder DAC to DE-15
General Description1

The pipeline is organized around one physical fact: the CPLDs contain no RAM (128 flip-flops per device), so no line buffer, tile fetch, or sprite shifter bank can exist on-chip. The only line-scale memory is the FIFO pair on each stream, and a FIFO’s contract is sequential delivery. The architecture therefore carries everything as two streams: PIXELS, a fixed-rate indexed data plane, and VIDCMD, a variable-rate control plane executed in lockstep with the beam. COMPOSITOR merges them per pixel slot; TIMING cancels every stage’s fixed latency by firing its comparators early (derived leads, not tuned).

Mechanisms3

Status stamps: PRODUCTION = RTL built, fitted, and testbench/suite verified. PRELIMINARY = design agreed, fit experiment pending — logic-cell figures are estimates until the fitter rules. ADVANCE = concept; specification may change.

3.1 PIXELS stream — indexed data plane PRODUCTION

ModeRateWords/linePixel meaning
1bpp direct1 bit/clk40bit selects pal_fg / pal_bg
2bpp micro-HAM2 bits/clk80dibit ops: 0_p held←pal[p]; 10_g_r, 11_g_b modify held chroma

Pure pixel bits — no in-band header (retired with rev 1). Palettes, mode, and pixel_skip arrive as VIDCMD SETs. On underrun PIXEL re-shifts its last word: one 0x0000 word paints background to end of line or frame (a compression feature, not an error path).

3.2 VIDCMD playback — beam-locked control plane PRODUCTION

RUN        { 2'b00, src[1:0],  ~count[11:0] }   src: 00 passthrough  01 held_fg  10 held_bg
RUN_COLOR  { 2'b00, 2'b11, colour[2:0], ~count[8:0] }   8 saturated corners, inline
SET        { 1'b1,  target[2:0], value[11:0] }  0 held_fg  1 held_bg  2..6 → PIXEL regs
reserved   { 2'b01, ... }                       1-slot no-op (mask record candidate, §3.5)

Every active pixel clock is one slot; a record occupies exactly one slot when it executes, with entry-edge commit: a SET’s effect is visible in the pixel of its own slot. When the count is terminal and nothing is staged, HOLD continues the current source — first-class framing (a whole passthrough frame costs one word). During blanking, staged SETs execute immediately in stream order (eager, and positional: a staged RUN blocks everything behind it). /RS at vsync resets held colors and all machine state.

3.3 Fetch engine — cadence and the banked pair PRODUCTION

The FIFO read strobe is a registered output: one word per 2 pixel clocks sustained. Two words bank ahead of playback — one in staged_word, one parked on Q (/RE held low; the 7200 holds Q valid indefinitely while /RE stays low). Laws, verified by 102 testbench checks and mirrored in the suite model:

LawStatement
L1Playback semantics unchanged by cadence: 1 slot/record, entry-edge commit, HOLD, positional eagerness
L2A RUN(N) banked before line start occupies slots 0..N−1; the next banked record executes slot N
L4Sustained cadence 2 slots/word; a 1-slot record in steady state paints 2 px (own slot + HOLD)
L5Banked-pair law: two banked records execute on consecutive slots; the third arrives 2 slots later

Consequences: a SET fg + SET bg pair behind any run ≥4 px lands on adjacent pixels (both palette entries change across two pixels); 1-px spans need ≥4-px pitch to land as authored (2–3-px pitch stretches them to 2 px); a back-to-back triple lands at slots N, N+2, N+4 relative to N−1.

3.4 SET conduit to PIXEL — the value bus PRODUCTION

PIXEL-target SETs cross on a dedicated 12-bit registered bus plus target/valid/commit (17 nets, all flop-to-flop). Constants: a SET is visible in its own slot; set_pix_commit leads its slot’s RGB_OUT by 1 clock; coincident commit+capture edges obey apply-old/capture-new. The K offsets are folded in by the list builder automatically — authoring is pixel-exact.

3.5 MASK record — per-pixel overlay PRODUCTION

MASK   { 2'b01, d1..d7 }  +  { d8..d15 }     16 px per 2-word record
pixel 0: IMPLICIT dibit {1,0} = opaque color0
dibit {opacity,select}: 00 passthrough · 10 color0 · 11 color1 · 01 reserved

Two words paint 16 pixels of per-pixel three-way choice (passthrough / color0 / color1). Played from staged_word shifted in place, data word reloaded from parked Q mid-record; adjacent masks chain gapless and a mask follows a RUN with zero gap (px0 is the record’s own first slot). Fitted at 121/128 LC — 4 cells cheaper than the rejected 8-px inline-color form, whose knife-edge color write also provably forced a 3-slot seam. Recolor via SET: measured seams — one SET between masks 2 slots, SET pair 4 slots (the mask holds the bank, so pairs cannot bank), RUN + SET pair + mask 3 slots. Authoring rules: leading transparency = a passthrough RUN before the record; glyphs wider than 15 px collide with the implicit px0. Full-line coverage: 80 words/line, under the delivery cap.

3.6 2bpp indexed mode PRODUCTION

Mode register bit 1 (bitwise decode; 11 reserved, HAM wins): PIXELS consumed 2 bits/clock as a direct index — zero new registers: 00→pal_bg, 01→pal_fg, 10→ham_held, 11→constant black. Four colors, three per-line settable via free hblank SETs. 80 words/line. Odd pixel_skip clamps to even (as HAM). One order rule: SET mode before SET ham_held — indexed mode locks the stream out of ham_held so code 10 shows the SET-loaded value. Fitted (PIXEL 105/128 incl. §3.7); tb + suite + emulator all express it (m8-indexed2 pixel-exact, 89 words/line with recolors vs the cap).

3.7 Half-rate flag — 320-wide modes PRODUCTION

Mode register bit 2: each consumed group held 2 pixel clocks — 320 effective pixels. 1bpp drops to 20 words/line, 2bpp indexed to 40; hardware-masked off in micro-HAM (the flag does nothing there, by one deliberate literal). COMPOSITOR never learns the rate: MASK dibits and SET boundaries stay full 640-px resolution over the chunky playfield (m9-halfrate: 0 split playfield groups, 1-px sprite detail on top). Vertical analog is free via line-repeat descriptors (§3.9).

3.8 LITERAL record — direct-color spans ADVANCE

“Next N VIDCMD words are raw R4G4B4 pixels.” At the 2-clock cadence each literal paints a 2-clock-wide pixel — which in a §3.7 half-rate mode is exactly one game pixel: full 12-bit per-pixel sprites and cursor at one word per game pixel, no palette involvement. COMPOSITOR decode + counter; specify after §3.5 fits.

3.9 Descriptor techniques — zero hardware PRODUCTION

ENGINE walks 4-word descriptors; the list is the machine. Line repeat (240-line modes), per-line palette/mode preambles, double-buffered lists re-armed from the vsync ISR (frame-owned RAM rule), and audio deposits woven into the same list (AUDIO_FIFO_W strobe) are all authoring, not silicon.

Screen-Mode Application Notes4

Words/line includes typical hblank SET preambles. Budget reference: ≈147 words/line at the 66% bus cap (§2).

Text console — 640×480, 2 colors/line≈43 words/line · 19% busPRODUCTION

Recipe: 1bpp stream (§3.1) + per-line SET pal_fg/pal_bg in hblank (§3.2, free) + RUN(passthrough, 640).

Notes: the shipping firmware console. Software font render into the framebuffer; attributes = per-line palette.

4-color bitmap — 640×480≈85 words/line · 38% busPRELIMINARY

Recipe: 2bpp indexed mode (§3.6) + hblank SETs for the three live entries.

Notes: per-line 4-color paint program / basic graphics target. Colors change per line for free.

Game mode — 320-wide, 4 colors + sprites≈60–80 words/line · ≤36% busPRELIMINARY

Recipe: half-rate 2bpp playfield (§3.7 + §3.6, 40 w/line) + MASK sprites (§3.5) + SET pairs for per-object color (L5 places them pixel-exact after any ≥4-px span).

Notes: “a step past Colecovision”: CV gives 4 single-color sprites/line; this gives delivery-bound sprite coverage (8 head-first / 32 interleaved spans/line measured), 12-bit color, arbitrary widths — color granularity per 16-px mask word rather than per sprite pixel. Line-repeat descriptors for 320×240 halve the stream again.

Cursor / sprites — 1-px-exact three-color overlay2 words per 16-px rowPRODUCTION

Recipe: one MASK record per row (§3.5): fill=color1, outline=color0, transparent surround; leading transparency via a passthrough RUN; wider sprites chain gapless.

Notes: spans-as-cursor is retired for 1-px art (4-px pitch floor, L4). Per-object recolor: SET seam 2–4 slots (§3.5) or place SETs in hblank for free.

Pure-VIDCMD screens — the display list is the framebufferconsole 82 w/line worst, 51 typical · kiosk 30PRODUCTION (modeled)

Recipe: no PIXELS fills at all — text and UI as MASK groups + RUN gaps + hblank SETs. m6-console: 80×60 text, two glyphs per record, pixel-exact vs reference. m7-kiosk: large text (15×28 glyphs in 16×32 cells — the implicit px0 dictates ≤15-px art), per-item colors, RUN_COLOR highlight bar.

Notes: with PIXELS empty, dibit-00 resolves to pal_bg in the model — a third settable color (hardware verification OPEN, §7). Every-group recoloring is impossible by construction (160 w/line > cap AND 800 slots > 640); sparse recoloring fits easily. Also the staged bring-up path: a working display before PIXEL is ever socketed.

Dual playfield — 2bpp under + 1bpp over≈125 words/line · 56% bus (worst case)PRELIMINARY

Recipe: 2bpp playfield in PIXELS + sustained full-line MASKs in VIDCMD (40 w/line, cadence-immune per §3.5).

Notes: exceeds the 66% cap only with every line dense; drop either plane to 320-wide to halve its cost.

Image viewer — high-fidelity stills≈80 words/line · 36% busPRODUCTION

Recipe: micro-HAM stream (§3.1) + per-line palette SETs. Suite-exact encoder in image-tools (ordered dither default, FS for photos).

Notes: chroma saturates (2 colors/line + 8 corners); infrequent update by design.

Vector / wireframe — RLE span listsdelivery-bound: ≈32 spans/linePRODUCTION

Recipe: per-line sorted span lists of RUN/RUN_COLOR (§3.2); vidcmd_plan_line() is the feasibility oracle at authoring time.

Notes: the Tempest case. 1-px features obey the 4-px pitch floor or ride MASKs. If cumulative gap-run authoring becomes painful, an absolute-X skip record (≈12–15 LC, COMPOSITOR) is the named upgrade — deferred.

VIDCMD Read-Port Timing5

Registered /RE against the 39.72 ns pixel clock. Worst-case parameters pinned 2026-08-18 from the IDT7200L15 and ATF1508AS-10 datasheets (griffin.yml interfaces:).

One read per pixel clock was evaluated and rejected structurally: with a gate-shaped half-period /RE, the guaranteed-valid window on Q ([tPD+tA, T/2+tDV] ≈ [23, 27] ns) overlaps neither capture edge — it misses the falling-edge requirement (12.9 ns) by ~10 ns and dies 6–13 ns before the rising-edge window (32.7 ns) opens. All alternate rescues (external ’574 latch, 2× fetch clock) stack unspecified ±2 ns quantities against 2–5 ns margins; and 1 word/clock would not solve per-pixel economics anyway (640 words/line = 2.5 FIFO fills). Per-pixel work belongs to MASK words, §3.5.

Programming Notes6
#Rule
PN1Each CUSHION line’s records must occupy exactly 640 slots as executed (the builder’s vidcmd_plan_line() simulation sizes trailing fillers; occupancy ≠ authored sum under cadence).
PN2Place a SET pair behind ≥4 px of playback (or in hblank) for consecutive-pixel commit; order the pair so the target needed first commits first.
PN3An overrunning record (>640 slots) plays at the start of the next line and blocks that line’s eager SETs — overrun steals eagerness.
PN4Any RAM a display list points at is frame-owned: double-buffer lists and data; re-arm from the vsync ISR (DESC write also acks the level-3 IRQ). The list must be idle before the ISR’s re-arm write — a DESC write mid-walk clobbers the walk; CTRL=0 abort is the safety net but forfeits the list’s remaining deposits.
PN5Two /RS deadlines, split by stream. Video-writing descriptors (PIXELS/VIDCMD /W) must complete before vsync: no video write strobe may overlap TIMING’s 318 ns nRS pulse (+15 ns setup / +10 ns after its rise). Audio-writing descriptors are exempt — AUDIO is not on the nRS net; its drain and both fill paths run straight through vblank. The re-armed list may open with audio-only descriptors immediately: ISR latency (≈3 µs minimum) outlasts the pulse. Do not stream video FIFOs before the first vsync (their first /RS).
PN61-px spans below 4-px pitch render 2 px wide (L4); use MASK words for sub-floor art.
