Features

  • VGA 640×480@59.94, R4G4B4 (12-bit) color throughout
  • Fixed-rate indexed pixel stream through a 16×12-bit palette RAM + beam-locked RLE command stream
  • Pixel-exact mid-line register writes (SET, banked-pair law)
  • MASK: 16 px of per-pixel three-way overlay in two words; masks chain gapless
  • LITERAL: one pixel of any R4G4B4 colour per word; LITERAL + HOLD is a flat span of any colour in two words
  • STREAM RUN: SETs recolour a run while it counts — fixed geometry, a late word only recolours late
  • Palette entries reloadable per line in hblank (3 words per entry, 8 per line)
  • 1 / 2 / 4 bpp and an attribute-word tile mode (TMS9918 Graphics II, inline)
  • No CPU bus on PIXEL / COMPOSITOR — all state in-band, palette included

Device Complement

  • ENGINE — ATF1508AS, descriptor DMA master (120/128 LC, 60/64 I/O)
  • PIXEL + TIMING — one ATF1508AS: stream unpacker, palette writer, raster + syncs + board time bases (123/128 LC, 94 FF, 43 I/O, fitter pass 1; pinout proposed, not frozen)
  • COMPOSITOR — ATF1508AS, VIDCMD playback incl. LITERAL / HOLD / STREAM RUN (118/128 LC, fitter pass 1; pinout proposed rev-2, not frozen)
  • Palette — 3× 16×4 separate-I/O bipolar RAM, 74F219 pinout (non-inverting; ≤22.7 ns address access required)
  • 2×2 IDT7200L15 FIFOs (256×9): PIXELS and VIDCMD streams, both read as ganged 16-bit ports
  • 2× 74AC541 + R4G4B4 ladder DAC to DE-15

Proposal revision. This sheet describes the indexed-PIXEL pipeline being landed on branch indexed-pixel: micro-HAM and PIXEL’s 12-bit colour registers retire, a palette RAM sits between PIXEL and COMPOSITOR, TIMING folds into the PIXEL chip, and the PIXELS FIFO is read 16 bits wide. Since 2026-10-03 COMPOSITOR also changed: RUN_COLOR is retired and its prefix carries LITERAL, the playback source’s fourth value is KEEP (HOLD records), a STREAM RUN lets SETs through while it counts, and the run counter is ten bits (§3.2, §3.8); RUN, SET and MASK words with counts up to 1023 are unchanged bit for bit. The indexed PIXEL, the palette write and the half-rate modes are production RTL with testbenches, shared model, suite, emulator, firmware and applications on the branch; nothing has run on hardware, and rev-1 boards cannot take this bitfile. PRELIMINARY still marks recipes that are authored but not yet exercised by an application. The shipped rev-1 description is this file at tag rev1-video.

General Description1

The pipeline is organized around one physical fact: the CPLDs contain no RAM (128 flip-flops per device), so no line buffer, tile fetch, or sprite shifter bank can exist on-chip. The only line-scale memory is the FIFO pair on each stream, and a FIFO’s contract is sequential delivery. The architecture therefore carries everything as two streams: PIXELS, a fixed-rate indexed data plane whose 4-bit indices address a small external palette RAM, and VIDCMD, a variable-rate control plane executed in lockstep with the beam. COMPOSITOR merges them per pixel slot; TIMING cancels every stage’s fixed latency by firing its comparators early (derived leads, not tuned).

3.1 PIXELS stream — indexed data plane PRODUCTION (branch)

Depthmode[1:0]Palette indexWords/line fullhalf rate
1bpp00{pix_base[3:1], bit} — one of 8 colour pairs4020
2bpp01{pix_base[3:2], dibit} — one of 4 colour quads8040
4bpp10nibble — the whole tableundefined80
attribute word11{fg4, bg4, pattern8} per 8-group cell: bit ? fg : bg8040

mode[2] is half rate (§3.7). Words are consumed MSB first; pure pixel bits, no in-band header. With the TMS9918 palette loaded, the attribute word is the Graphics II colour byte followed by the pattern byte: a tile background is words copied from tables, scrolled by moving descriptor pointers. At full rate the same mode is 80-column cell-coloured text. 4bpp at full rate is over the line budget and desynchronizes the frame; do not select it. Mode, base and skip arrive as VIDCMD SETs in blanking; mode may differ line to line. On underrun PIXEL re-shifts zeros: index 0 of the current base.

pixel_skip (4 bits, stream bits) is a start position inside the line’s first word; coarser scrolling moves the source pointer by words. Clamps: 2bpp to even, 4bpp to multiples of 4, attribute mode ignores skip. Recorded limits: 1bpp 15 acts as 14; 2bpp full rate 14/15 act as 12. A line with non-zero skip consumes one extra word (the author supplies it) and its tail shows real data. Skip is sampled at the line’s preload — set it before the line.

3.2 VIDCMD playback — beam-locked control plane PRODUCTION

RUN        { 2'b00, src[1:0], 2'b11, ~count[9:0] }   src: 00 passthrough  01 cmp_color1  10 cmp_color0   count 1..1023, 0 = 1024
STREAM RUN { 2'b00, src[1:0], 2'b10, ~count[9:0] }   a RUN during which staged SETs execute (§3.8)
HOLD       { 2'b00, src≠11, 1'b0, x, ~count[9:0] }   KEEP for count slots (src ignored)
LITERAL    { 2'b00, 2'b11, colour[11:0] }            one pixel of any R4G4B4 colour, then KEEP (§3.8)
MASK       { 2'b01, d1..d7 } + { d8..d15 }      two words, 16 px; pixel 0 implicit opaque cmp_color0 (§3.5)
SET        { 1'b1,  target[2:0], value[11:0] }  0 cmp_color1  1 cmp_color0  2 clut_index  3 clut_data
                                                4 pix_base  5 pix_mode  6 pixel_skip  7 filler (PIXEL ignores)

Six record types, one word each except MASK. Target 0 writes cmp_color1 and target 1 writes cmp_color0; the number/name mismatch is a frozen wire contract (super-engine/descriptor.h). Counts are stored complemented in a ten-bit field; bits 11:10 are the run-class kind (11 RUN, 10 STREAM RUN, 0x HOLD), and a count of 0 is not a no-op (it is a 1024-slot run). The source is one of four: passthrough, cmp_color1, cmp_color0, or KEEP — RGB_OUT fed back, repeating the last colour shown on the line (black at a line’s start and across blanking). Compatibility: an old twelve-bit RUN of count 1..1023 is the same word bit for bit; an old 1024..2047 now decodes as a STREAM RUN and 2048..4095 as a HOLD (no well-formed line had them). RUN_COLOR ({00, 11, colour[2:0], ~count[8:0]}, eight corner colours) was retired 2026-10-03: its prefix is LITERAL, so an old RUN_COLOR word now plays as a literal of an unrelated colour.

Every active pixel clock is one slot; a record occupies its count of slots (SET one, MASK sixteen) when it executes, with entry-edge commit: a SET’s effect is visible in the pixel of its own slot. When the count is terminal and nothing is staged, HOLD continues the current source — first-class framing (a whole passthrough frame costs one word). During blanking, staged SETs execute immediately in stream order (eager, and positional: a staged RUN or MASK header — or a LITERAL, HOLD or STREAM RUN — blocks everything behind it). /RS at vsync resets all machine state: cmp_color1 = FFF, cmp_color0 = 000, source passthrough (never KEEP), the literal’s bank hold and the streaming flag cleared. What a record costs to deliver is a separate number from what it costs to execute (§3.3, §6.1).

3.3 Fetch engine — cadence and the banked pair PRODUCTION

The FIFO read strobe is a registered output: one word per 2 pixel clocks sustained. Two words bank ahead of playback — one in staged_word, one parked on Q (/RE held low; the 7200 holds Q valid indefinitely while /RE stays low). Laws, verified by 102 testbench checks and mirrored in the suite model:

LawStatement
L1Playback semantics unchanged by cadence: 1 slot/record, entry-edge commit, HOLD, positional eagerness
L2A RUN(N) banked before line start occupies slots 0..N−1; the next banked record executes slot N
L4Sustained cadence 2 slots/word; a 1-slot record in steady state paints 2 px (own slot + HOLD)
L5Banked-pair law: two banked records execute on consecutive slots; the third arrives 2 slots later

Consequences (hand-derived from the fetch rules and reproduced by the shared model; the testbench exercises the RUN(4) form): any RUN or HOLD of ≥2 px ends exactly where authored, and a LITERAL is always exactly 2 (it never heads a pair, §3.8); every run of ≥3 px re-arms the pair, so the two records behind it land on consecutive pixels (a SET color1 + SET color0 pair changes both colours across two pixels); the third and later 1-slot records land every other pixel (N, N+1, N+3, N+5…). A run of exactly 2 keeps its own boundary exact but re-arms the pair only when the record behind it was already parked. 1-px features therefore land as authored at ≥4-px pitch (RUN 3 + feature) and stretch to 2 px at 2–3-px pitch. Authoring rules of thumb: §6.1.

3.4 SET conduit to PIXEL — the value bus PRODUCTION

PIXEL-target SETs cross on a dedicated 12-bit registered bus plus target/valid/commit (17 nets, all flop-to-flop). Constants: a SET is visible in its own slot; set_pix_commit leads its slot’s RGB_OUT by 1 clock; coincident commit+capture edges obey apply-old/capture-new. The K offsets are folded in by the list builder automatically — authoring is pixel-exact.

3.5 MASK record — per-pixel overlay PRODUCTION

MASK   { 2'b01, d1..d7 }  +  { d8..d15 }     16 px per 2-word record
pixel 0: IMPLICIT dibit {1,0} = opaque color0
dibit {opacity,select}: 00 passthrough · 10 color0 · 11 color1 · 01 reserved

Two words paint 16 pixels of per-pixel three-way choice (passthrough / color0 / color1). Played from staged_word shifted in place, data word reloaded from parked Q mid-record; adjacent masks chain gapless and a mask follows a RUN with zero gap (px0 is the record’s own first slot). Fitted at 121/128 LC when measured (122/128 in the 2026-08-26 production fit; 118/128 with LITERAL/HOLD/STREAM RUN, §3.8) — 4 cells cheaper than the rejected 8-px inline-color form, whose knife-edge color write also provably forced a 3-slot seam. Recolor via SET: measured seams — one SET between masks 2 slots, SET pair 4 slots (the mask holds the bank, so pairs cannot bank), RUN + SET pair + mask 3 slots; mask px15 → literal 0 slots. Over a KEEP span the restored source is KEEP, which repeats the mask’s last pixel: re-issue the literal after a mask laid over a literal span. Authoring rules: leading transparency = a passthrough RUN before the record; glyphs wider than 15 px collide with the implicit px0. Full-line coverage: 80 words/line, under the delivery cap.

3.6 Palette RAM — load and reload PRODUCTION (branch)

SET clut_index names an entry; SET clut_data writes its 12-bit colour: PIXEL puts clut_index on IDX for clocks 1–3 after the commit and pulses /CLUT_WE low on clock 2 alone — a full clock of address and data setup before the pulse and a full clock of hold after it — while the value is still on set_pix_value, which is wired to the RAM’s data inputs. COMPOSITOR re-registers that bus from every staged word and stages one every two clocks, so the data SET covers clocks 0–1 only and must be followed by one filler that leaves the bus unchanged: SET target 7 with the same value (measured necessary and sufficient; any other following word stores the wrong colour). Three words per entry. The RAM is never reset and powers up undefined — software loads what it uses (16 entries in vblank = 48 words); contents persist across frames.

A write takes over the pixel bus for a few clocks (RAM outputs float while /WE is low, then need write recovery), so it is legal only in blanking or under a non-passthrough RUN / opaque MASK: clocks 1–4 after the commit (1–3 measured on RGB_IN, plus one guard clock for write recovery), so the word after the filler must not be the RUN that resumes passthrough. Pinned by clut_pair_tb.v (COMPOSITOR + PIXEL + RAM model), which also fails the rejected later pulse for giving the RAM zero data hold.

3.7 Half-rate flag — 320-wide modes PRODUCTION (branch)

Mode register bit 2: each consumed group held 2 pixel clocks — 320 effective pixels. 1bpp drops to 20 words/line, 2bpp and the attribute word to 40; 4bpp exists only at half rate (80). COMPOSITOR never learns the rate: MASK dibits and SET boundaries stay full 640-px resolution over the chunky playfield. Vertical analog is free via line-repeat descriptors (§3.9).

3.8 LITERAL, HOLD and STREAM RUN — direct colour and streamed recolour PRODUCTION (branch)

Landed 2026-10-03 in place of RUN_COLOR: RTL fitted, compositor_tb.v cases derived on paper before simulation, the shared model equation-for-equation (56 bench-derived traces in the suite, the planner included), suite cases, emulator. LITERAL paints its own slot in its colour and leaves the source at KEEP. Its colour is read out of staged_word during the clock after its consume edge, so it holds the on-chip bank for one clock: the next word parks instead of being captured. Law LL: a literal always paints at least two slots and whatever follows it executes two slots later, banked or not — one 320-density pixel, the half-rate playfield’s own density. A literal can be a banked pair’s second record, never its head. HOLD(N) is KEEP for N slots, so LITERAL + HOLD(N) is a flat span of any colour in two words. STREAM RUN sets a streaming flag: a staged SET executes on the next active edge without waiting for the terminal while the count runs on untouched (laws LS1..LS5: geometry is the run’s; only SETs stream; each at the ordinary cadence; a late SET recolours late; leftovers at the terminal execute as ordinary SETs and push the line out).

Late words. A late SET inside a stream run recolours late and moves nothing; a late literal delays everything after it (suite m14 (d): the stream form’s line still ends on its slot and the next line is unshifted; the literal form lands 6 slots late and overruns into the next line). The model counts SETs left over at a stream run’s terminal as a fault (vidcmd_stream_leftovers): a run needs 2k slots for k SETs. Streaming is an active-video rule — a SET behind a staged stream run is not eager in blanking.

Fit. 118/128 LC, fitter pass 1, tightest block fan-in 34/40, on a PROPOSED rev-2 pinout, NOT FROZEN: the literal’s colour reaches RGB_OUT through a new per-bit input, so four RGB_OUT bits moved to block G (RGB_OUT_3/0/1/2 → pins 63/64/65/67, swapped with VIDCMD_Q_10/11/8/13 → 49/50/51/52) and no logic block carries more than four RGB_OUT bits. At this density the fit is fitter luck — declaration order alone flipped fit and no-fit — so any edit to the logic is a re-fit. Ladder: cpld/experiments/literal/RESULTS.md (rung R4st, p444g).

3.9 Descriptor techniques — zero hardware PRODUCTION

ENGINE walks 4-word descriptors; the list is the machine. Line repeat (240-line modes), per-line palette/mode preambles, double-buffered lists re-armed from the vsync ISR (frame-owned RAM rule), and audio deposits woven into the same list (AUDIO_FIFO_W strobe) are all authoring, not silicon.

3.10 TIMING fan-out — the board’s one time base PRELIMINARY (relocating)

Rev 3: the TIMING logic moves unchanged into the PIXEL chip; the laws below and timing_tb.v still govern it. Pin numbers in this section are the retired ATF1504 part’s; the merged chip’s pinout is “proposed rev-2, not frozen” until the board is routed. DUART OP4..OP7 are no longer reserved on any pin; they float until a raster/rate selector is designed.

TIMING has no CPU bus and no input but clock and reset, so every output is a closed-form function of (h_cnt, v_cnt), and every one is registered — the extra pipeline stage the DAC_LEAD of 4 (§2) already absorbs. Besides the video outputs (VGA_HSYNC / VGA_VSYNC, nRS, H_ACTIVE, PIX_CONSUME / PIX_PRELOAD / PIX_LAST) it now carries the four off-video nets whose consumers need an edge no CPU stall can jitter:

OutputPinConsumerLaw
HBLANK19ENGINE pin 2 (wait_hblank pacing edge, synchronized rise)High for h_cnt 640..799 on every line, blank or visible; rises on the same clock PIX_CONSUME falls on a visible line. This is the start of the 160-clock blank the super-engine budgets (descriptor.h HBLANK_SYSCLK), not the HSYNC rise 116 clocks later. Previously unpinned for rev 2.
nVSYNC_IRQ31GLUE pin 65 (level-6 vsync IRQ latch)Identical waveform to VGA_VSYNC today (negative, 2 lines at v = 490..491), but its polarity is fixed for all time regardless of any future raster mode. Replaces the earlier plan of tee’ing VGA_VSYNC pre-buffer to GLUE.
PADDLE_TICK17PORTS pin 44Square wave toggling at the start of every line — 15.734 kHz, 31.8 µs half-periods — free-running from reset with no frame-boundary exception. PORTS counts FALLING edges only, so paddles count at the Atari 2600 scanline rate (full scale 255 = 16.2 ms, about one frame).
AUDIO_TICK18PORTS pin 45Same law, separate register on a separate net so the audio rate can change later without touching the paddles. The audio FIFO pop stays at AUDIO_SAMPLES_PER_SECOND 15734.

Square waves, not pulses: a one-pixel-clock pulse (39.7 ns) is narrower than one SYSCLK and PORTS’ synchronizer would miss it. Falling-edge-only on the PORTS side is a fit result, not a taste — a both-edges XOR detector doubles the product terms in every PORTS paddle-counter bit and PORTS fails routing (measured negative result); falling-edge-only fits at 122/128. HSYNC is no longer tapped by PORTS: VGA_HSYNC / VGA_VSYNC now go only to the 74AC541 buffers and the connector. Fit 35/64 LC, 15/32 I/O, -preassign keep with the production strategy flags (JTAG on, TDI/TMS pullups, power_reset on); the four new pins were appended to the frozen //PIN block and the original nine did not move. Pins 20 / 21 / 24 / 25 were reserved for DUART OP4..OP7 on the rev-2 part; that reservation is withdrawn (rev-3 note above) and OP4..OP7 float until a raster/rate selector is designed. GCLK2 (pin 44) is left free for an optional second oscillator. These new pins are bitfile-usable only because the schematic routes them.

Screen-Mode Application Notes4

Words/line includes typical hblank SET preambles. Budget reference: ≈147 words/line at the 66% bus cap (§2).

Text console — 640×480, 2 colors/line≈43 words/line · CPU keeps 76%PRODUCTION (branch)

Recipe: 1bpp stream (§3.1) + two palette entries loaded in vblank + RUN(passthrough, 640). Per-line colour = SET pix_base in hblank picking one of 8 preloaded pairs (1 word), or palette rewrites (3 words each).

Notes: the firmware console. Software font render into the framebuffer. An ST-style mono desktop is the same recipe with entries 0/1 swapped.

Cell-coloured text — 80 columns, fg/bg per character≈83 words/linePRELIMINARY

Recipe: attribute word at full rate (§3.1): one word per 8-pixel cell per line carries both colours and the glyph row.

Notes: any 2 of 16 colours per character cell; no character generator — software writes glyph rows into the words.

4-color bitmap — 640×480≈83 words/line · CPU keeps ~52%PRELIMINARY

Recipe: 2bpp (§3.1); pix_base selects which quad of the palette, switchable per line with one SET.

Tile game — 320-wide, 16 colors, static background + sprites40 words/line + sprite recordsPRELIMINARY

Recipe: attribute word at half rate (§3.1, §3.7) built once per screen from tile tables; scroll by descriptor pointer; the VIDCMD line program carries only sprites (MASK / RUN, §3.5) in direct 12-bit colour.

Notes: the ColecoVision-port shape (Smurf): nothing is re-encoded when a sprite moves except that sprite’s own records. 16-colour alternative: 4bpp half rate at 80 words/line.

16-color bitmap — 320×480 (or 320×240 by line repeat)≈83 words/line · CPU keeps ~52%PRODUCTION (branch)

Recipe: 4bpp half rate; fine horizontal scroll by pixel_skip 0/4/8/12 plus the word pointer; vertical scroll by descriptors.

Notes: a static 320×240 screen needs no per-line VIDCMD at all: mode, base and palette go out once in the vblank preamble and each line is 80 PIXELS words in three descriptors, both scanlines of a pair pointing at the same row. Exercised by apps/mandelbrot, whose emulator screenshots are compared pixel-exact with a host render.

Literal sprite row — any colour per pixel, 320 density1 word per source pixelPRODUCTION (modeled)

Recipe: lead RUN(pt, x), then one LITERAL per opaque source pixel and RUN(pt, 2) per transparent one, then the exit RUN. Every element is exactly two slots, so a 16-pixel row is 32 slots and exact at every x, x = 0, 1, 2 included (the SET-stream form could not do x = 0 or 2); at the right edge exact up to x = 608, beyond that clip the elements that do not fit. Suite m14 (a): pixel-exact over the 4bpp half-rate and attribute playfields at x = 0, 1, 2, 301, 608 and 624 (clipped).

Painter’s order by slicing: back[0..a) + front[all] + back[b..16), three descriptors at sub-ranges of static rows — no fix-up word at any seam, because every element is a two-slot record and any record after a literal is +2. The price is the notch: the front’s transparent pixels show the backdrop, not the back sprite. m14 k1-sliced, pixel-exact, one line of lookahead.

Delivery: a row consumes one word per 2 slots against ENGINE’s one per ≈3.6 pixel clocks, so rows are buffered, never trickled: word j of a row at x must be in the FIFO by slot x + 2j − 4. A 17-word left-edge program first in its own HBLANK group has its last word 55 SYSCLK after the edge (measured margin +33 SYSCLK before pixel 0) and the first PIXELS word at 71 < 80 SYSCLK (PIX_PRELOAD). With k = 1 (pieces behind the PIXELS words) the margin is +232 SYSCLK; PIXELS-first at k = 0 misses by 169 (negative control).

Flat span — any colour, any width ≥ 4 (or exactly 2)2 wordsPRODUCTION (modeled)

Recipe: LITERAL(c) + HOLD(n − 2) paints n slots behind a long record, max(n, 4) in general; a bare LITERAL is exactly 2. Widths 1 and 3 cannot be painted this way: use a held colour, RUN(cmp_color1/0, n) — one word, any width, timed exactly as RUN_COLOR was — or a MASK. A black span at a line’s start can be a bare HOLD(n), since KEEP is black there.

One-pixel patch at 640 density: not a literal (always 2 slots). RUN(pt, n) RUN(cmp_color1, 1) RUN(pt, …) with cmp_color1 preloaded in hblank is exact behind a long run (the pair law, RT3/RT4).

Cursor / sprites — 1-px-exact three-color overlay2 words per 16-px row · cursor 4 words/linePRODUCTION

Recipe: one MASK record per row (§3.5): fill=color1, outline=color0, transparent surround; leading transparency via a passthrough RUN; wider sprites chain gapless.

Notes: spans-as-cursor is retired for 1-px art (4-px pitch floor, L4). Per-object recolor: SET seam 2–4 slots (§3.5) or place SETs in hblank for free.

Default — per-line records (apps/lib/griffin_cursor.h): every visible line’s group carries one VIDCMD descriptor of four words, delivered one line early (line L’s behind line L−1’s PIXELS; line 0’s as the last vblank item, after /RS). A line without the cursor points at one shared blank record FILLER FILLER FILLER RUN(pt, 640); the sixteen cursor lines point at sixteen row records gap MASK-header MASK-data tail with gap = RUN(pt, c) and tail = RUN(pt, 624 − c), c = x + the row’s first opaque column. Every line sums to exactly 640 on its own: no hold framing, nothing carried across a line end. Edges: there is no zero-count RUN, so an empty gap (c = 0) or tail (c = 624) is a FILLER in the same word (zero slots in front of the first playback record, and zero behind a mask ending on slot 639, where it is consumed in blanking); rows below line 479 are simply not pointed at; and because a MASK is always 16 slots with pixel 0 opaque, a row whose first opaque pixel is right of column 624 cannot be drawn inside its line and is left off (the arrow vanishes for x > 624, its offset-5 bottom row from x = 620; clamp the hot spot to 624, or to 619 to keep it whole). Cost: 22 SYSCLK per line, 10,560 SYSCLK = 4.5% of a field (measured = derived); an x move is at most 3 word stores per row (gap, tail, one re-point), a y move at most 32 re-points of one word each; no multiply. Tearing: gap and tail are separate stores, and a line delivered between them sums to 639 or 641 and shifts the rest of the frame, so edit only a list that is not playing (two lists, each with its own records). Suite m15-cursor-per-line: pixel-exact at x = 0, 1, 2, 3, 319, 619, 620, 623–625, 638, 639 and y = 0, 1, 100, 240, 464, 465, 479 under both render drivers, through a sequence of x, y and diagonal moves, with negative controls (639- and 641-slot rows, a stale descriptor, k = 0 delivery) that fail; worst delivery margin 316 SYSCLK before pixel 0, derived 315–316. apps/mandelbrot uses it.

Advanced — whole-frame chain (apps/lib/griffin_cursor_chain.h): for a screen with no other VIDCMD content, a cursor needs no per-line records. Slots are active pixel clocks only, 640 per line, so raster (x, y) is slot y·640 + x of the frame: deliver passthrough RUNs totalling that, then one MASK per row separated by passthrough RUNs, then a one-slot RUN. With the ten-bit counter the lead-in is up to 301 RUNs of 1023, so the chain is a fixed 350 words delivered in two fixed parts: 192 words in the vblank preamble behind the 52 fixed words (244), and 158 in 32-word chunks behind the PIXELS of lines 184–188, each at least 41 lines before it can be needed; FIFO peak 233 derived, 230 measured. About 850 SYSCLK a field instead of 10,560, at the price of a hand-proved deadline and FIFO bound. Because a record may run off the right edge and resume on the next line (its off-screen dibits authored as passthrough), the chain clips exactly at the right edge, which the per-line form cannot. Suite case m12-cursor-chain, pixel-exact at ten stress positions under both render drivers.

One read per pixel clock was evaluated and rejected structurally: with a gate-shaped half-period /RE, the guaranteed-valid window on Q ([tPD+tA, T/2+tDV] ≈ [23, 27] ns) overlaps neither capture edge — it misses the falling-edge requirement (12.9 ns) by ~10 ns and dies 6–13 ns before the rising-edge window (32.7 ns) opens. All alternate rescues (external ’574 latch, 2× fetch clock) stack unspecified ±2 ns quantities against 2–5 ns margins; and 1 word/clock would not solve per-pixel economics anyway (640 words/line = 2.5 FIFO fills). Per-pixel work belongs to MASK words, §3.5.

Revisited 2026-09-22..24, closed (griffin.log 2026-09-24). Working back from any capture edge C with the pinned numbers: the fall’s clock edge must sit no later than C−32 (tCO 8 + tA 15 + flight 2 + tSU 7), the rise’s no earlier than C−8 (tCO min 3 + tDV 5, tH 0), and the next fall at least 15 ns after the rise (tRR 10 + the 5 ns tCO spread): 39 ns per read against a 39.72 ns period, 0.7 ns of slack. Any /RE low time L gives a guaranteed Q window of L−10 ns, so the half-period pulse (rising-edge assert / falling-edge release, or the mirror, or a 74AC00 shaping the clock) leaves a 10 ns window that no edge reaches; a 50.35 MHz quadrature clock (10 ns edge grid) or a 2× fetch clock cannot land inside 0.7 ns either. The only sound route to one word per clock is reading two FIFO pairs at once (32 more COMPOSITOR inputs, which the 64/64 part does not have), or faster parts (IDT7200L12 + ATF1508AS-7 would open the chain to roughly 14 ns of slack — figures to be read from those datasheets before relying on them). Authoring Rules and Limitations6

6.1 Rules of thumb for a line program PRODUCTION (model)

The short form a developer can hold in their head. Derived by hand from the fetch rules (§3.3) and reproduced by the shared fetch-engine model on 2026-09-24 (griffin.log 2026-09-24); the testbench pins the constants they rest on (2-slot cadence, pair gap 1, mask seams). Runs for anything 2 px or wider, one pair of fine records free after every run of 3 or more, masks for anything finer.

#Rule of thumb
RT1Per-pixel detail is MASK. Sixteen pixels per two words, each pixel passthrough, cmp_color0 or cmp_color1, pixel 0 always cmp_color0. Masks chain with zero seam, and a mask directly after a RUN starts exactly where the run ends. Changing a colour between masks (mask, SET, mask) costs 2 px of seam; so does a 1-px held-colour RUN between masks. A literal after a mask costs nothing (px15 → literal 0).
RT2Any RUN or HOLD of 2 px or more ends exactly where you said, and a LITERAL is always exactly 2. Boundaries are free at any x; alternating 2-px runs and literals render pixel-exact across the whole line, so a literal sprite row is exact at every x. LITERAL + HOLD(n) is max(n+2, 4).
RT3Every RUN of 3 px or more re-arms the pair. The two records behind it fire on consecutive pixels, whatever they are (SET then SET, SET then RUN, RUN then MASK) — except that a LITERAL never heads the pair: the record behind it is +2. The third and later 1-px records land every other pixel until the next run of 3 or more. A run of exactly 2 keeps its own boundary exact but only sometimes re-arms; do not count on it.
RT4A 1-px record is exact inside the pair and costs 2 px outside it. After a long run: one 1-px feature is free, two are free, three cost. Outside the pair a 1-px SET or RUN paints its pixel plus a HOLD pixel of the same colour. Measured on the model after RUN(10), with RC×1 a one-slot record (it was RUN_COLOR; a held-colour RUN(c,1) times identically): RC×1, RUN → 10, 11; RC×1 ×2, RUN → 10, 11, 13; RC×1 ×3, RUN → 10, 11, 13, 15. A LITERAL is never a 1-px record. Repeated 1-px features are exact at 4-px pitch (RUN 3 + feature) and stretch at 2–3-px pitch.
RT5HOLDs are insertions, not overwrites. Everything after a HOLD shifts right by one pixel and the line must still occupy exactly 640 slots (PN1), so a list with more than one 1-px record per run goes through vidcmd_plan_line() or the Line Player page, not a hand sum.
RT6Blanking is free. SETs execute in hblank at zero pixel cost and 160 clocks hold 80 words, so colour setup and palette writes belong there. A palette write inside active video steals the four pixels after the DATA SET; cover them with a colour run, a LITERAL/HOLD span or an opaque mask (PN8).
RT8Recolour without moving: STREAM RUN. SETs behind a stream run execute inside it at the ordinary cadence (first at +1 when banked with it, then every 2) and cost no slots; give the run 2k slots for k SETs or the leftovers push the line out. A late SET only recolours late. Under an ordinary RUN the same SETs still wait for its end.
RT7The per-line budget is delivery, not fetch. About 147 words from ENGINE per line and 256 in the FIFO (§2). A full-line mask is 80 words, so two-colour per-pixel detail across the whole width is affordable; the fetch cadence only sets local pitch, never the line total.

6.2 Rules and limitations PRODUCTION

#Rule
PN1Each CUSHION line’s records must occupy exactly 640 slots as executed (the builder’s vidcmd_plan_line() simulation sizes trailing fillers; occupancy ≠ authored sum under cadence).
PN2Place a SET pair behind ≥3 px of playback (RT3; the testbench pins the ≥4 form) or in hblank for consecutive-pixel commit; order the pair so the target needed first commits first.
PN3An overrunning record (>640 slots) plays at the start of the next line and blocks that line’s eager SETs — overrun steals eagerness.
PN4Any RAM a display list points at is frame-owned: double-buffer lists and data; re-arm from the vsync ISR (DESC write also acks the level-3 IRQ). The list must be idle before the ISR’s re-arm write — a DESC write mid-walk clobbers the walk; CTRL=0 abort is the safety net but forfeits the list’s remaining deposits.
PN5Two /RS deadlines, split by stream. Video-writing descriptors (PIXELS/VIDCMD /W) must complete before vsync: no video write strobe may overlap TIMING’s 318 ns nRS pulse (+15 ns setup / +10 ns after its rise). Audio-writing descriptors are exempt — AUDIO is not on the nRS net; its drain and both fill paths run straight through vblank. The re-armed list may open with audio-only descriptors immediately: ISR latency (≈3 µs minimum) outlasts the pulse. Do not stream video FIFOs before the first vsync (their first /RS).
PN61-px records outside the banked pair render 2 px wide (L4, RT4): exact at ≥4-px pitch, stretched at 2–3-px pitch; use MASK words for sub-floor art. A LITERAL is always 2 px, so 1-px colour marks are held-colour RUNs or MASKs.
PN7The line’s first PIXELS word is read 16 pixel clocks before the line starts (PIX_PRELOAD), and pix_mode, pix_base and pixel_skip are sampled on that same clock. The word must already be in the FIFO and those SETs already executed by then: the usable part of the 160-clock blank is about 144 clocks (≈80 SYSCLK), which a full 26-word hblank packet plus its descriptor overheads nearly fills. Deliver a line’s PIXELS words early (the FIFO holds 256; PIXEL stops reading at the end of each line) rather than after a long packet. Found by the clocked model; slack on hardware is unverified (§7).
PN8Palette entries cost three words — SET clut_index, SET clut_data, then SET target 7 carrying the same value — and the four pixel clocks after the data SET must be blanking or covered by a non-passthrough RUN (a STREAM RUN over a colour register qualifies; over passthrough it does not, and the model flags it), a LITERAL/HOLD span (KEEP and a literal’s slot never read the RAM) or an opaque MASK; the word after the filler must not be the RUN that resumes passthrough (§3.6). Mid-line recolouring of passthrough pixels is done with SET pix_base (one word, pairs or quads preloaded), never with a palette write.
PN9The palette RAM is never reset and powers up undefined: load every entry a screen can show, each frame or once per screen. Registers return to 0 at every vsync (pix_mode, pix_base, pixel_skip, clut_index); the palette does not.
PN10pixel_skip limits: 2bpp even values, 4bpp multiples of 4, attribute mode ignores it; 1bpp 15 acts as 14, 2bpp full rate 14/15 act as 12. A line with non-zero skip consumes one extra PIXELS word, which the list must supply. Skip set mid-line applies to the next line.
PN114bpp exists only at half rate; selecting it at full rate desynchronizes the rest of the frame. Change pix_mode in blanking only; a mid-line change is undefined.
PN13What replaces RUN_COLOR (retired 2026-10-03): a flat span is LITERAL + HOLD(n − 2), two words, any colour, n ≥ 4 or exactly 2; widths 1 and 3 are a held-colour RUN or a MASK; a black span opening a line is a bare HOLD. Old RUN words of count 1..1023 are valid bit for bit; counts above 1023 must be split (the encoders clamp). KEEP at a line’s start, and carried across blanking, is black: open every line with a real source.
PN14A MASK laid over a KEEP span restores KEEP, which repeats the mask’s last pixel, not the colour underneath: re-issue the LITERAL after the mask. Painter’s order between literal rows is done by slicing (no fix-up word at any seam); the front’s transparent pixels then show the backdrop, not the back row.
PN12Budget, not resolution, is the usual limit: PIXELS words plus VIDCMD words share about 147 words per line, and video DMA leaves the CPU roughly 76% (1bpp console), 56% (pure-VIDCMD text) or 52% (80-word playfield) — emulator cost model (§2).
