Features

  • Stereo 8-bit two’s complement output at 15,734.375 Hz, tick-locked to the raster (262.5 ticks per field)
  • SAMPLES stream: PCM pairs deposited by ENGINE DMA, no CPU path (rev 1 production)
  • AUDCMD stream: beam-locked WAIT / SET records driving a time-shared voice engine (proposal)
  • 8 voices in an 8K×8 SRAM: square and wavetable (LFSR noise did not fit, §7); 16-bit phase, signed 8-bit amplitude, L/R pan
  • Phase-continuous volume; a missed vblank holds the notes, it never silences them
  • PCM passthrough mixed digitally under the voices; saturating on every add
  • No CPU bus on MIXER — every voice byte is set in band through the AUDCMD FIFO

Device Complement

  • ENGINE — existing descriptor DMA master; AUDIO_FIFO_W and SPARE strobes, no change
  • 2× IDT7200L15 — SAMPLES pair, {L, R} per word, 256 deep (rev 1, in place)
  • 2× IDT7200L15 — AUDCMD pair, one 16-bit record per word (new)
  • MIXER — ATF1508AS: tick sequencer, one 8-bit adder walked over the voices, one saturating accumulator, two passes, both FIFO read ports, WAIT field (rung ii: 128/128 LC, 60 FF, 44/64 I/O, pass 1, zero spare cells)
  • 8K×8 SRAM — voice state, wave tables, WAIT field: MCM60L64P10 (100 ns) from the bin; the KM6264L-15 has no timing table for its grade (§5)
  • 2× 74HC574 DAC latches on one shared byte, driving the existing R-2R ladders, LM358 stage and 3× LM386; the rev-1 CD4049 MSB inverters are removed, MIXER emits offset binary
  • PORTS — rev-1 pop logic (AUDIO_CONTROL / AUDIO_STATUS) retires into MIXER

Proposal revision. Rev 1 ships the SAMPLES path only (§3.1): ENGINE fills a FIFO pair and PORTS pops it to the DACs. Everything from §3.2 on is the MIXER proposal being worked on 2026-09-26: the host model and its A/B against the SN76489 recording have passed their gate; the first fit rung fitted the voice walk but not the whole chip; the second rung is the decisive gate, and if it fails without a limitation the owner accepts, the sound processor becomes a Z80 (wave-table-design.md §3 step 4). Nothing in §3.2 onward has run on hardware, and rev-1 boards cannot take it. PRELIMINARY marks mechanisms modelled and fitted in part; ADVANCE marks concepts; OPEN marks a question the gate has not answered.

General Description1

The audio pipeline is shaped by the same fact as the video pipeline: the CPLDs hold no RAM, so anything that must remember more than a hundred bits lives in a FIFO or an external SRAM. Sound therefore travels as two streams, in deliberate symmetry with PIXELS and VIDCMD. SAMPLES is a fixed-rate data plane: one {L, R} pair per tick, deposited by ENGINE and consumed whether or not anyone is listening. AUDCMD is a variable-rate control plane: WAIT and SET records that occupy ticks the way VIDCMD records occupy pixel slots. MIXER consumes both, keeps every voice’s state in the SRAM, and produces one stereo pair per tick by walking the voices through one adder. The CPU never touches a voice register; it writes records into RAM and points a descriptor at them.

Mechanisms3

Status stamps: PRODUCTION = RTL built, fitted, verified; on rev-1 boards for §3.1. PRELIMINARY = laws pinned in wave-table-design.md §2, modelled in mixer/mixer.h, fitted in part. ADVANCE = concept, specification may change.

3.1 SAMPLES stream — PCM data plane PRODUCTION (rev 1)

ENGINE deposits one {L, R} word per AUDIO_FIFO_W strobe into the pair; nothing else can write it. On rev 1, PORTS pops both chips on every AUDIO_TICK falling edge while AUDIO_CONTROL.ENABLE is set, and the DACs hold the last pair when the FIFO runs dry. AUDIO_CONTROL.RESET (reset value 1) holds both /RS low; AUDIO_STATUS.EMPTY is the raw /EF pin, polled, with no interrupt. Flush sequence: ENABLE=0, RESET=1, RESET=0, deposit, ENABLE=1, and RESET may only change while no list that deposits AUDIO_FIFO_W is armed.

Under MIXER the pair stays exactly as built and the pop moves: MIXER reads the L chip at the start of pass 0 and the R chip at the start of pass 1 as each channel’s accumulator seed, or seeds 0 when /EF says empty. The rev-1 registers retire.

3.2 AUDCMD stream — tick-locked control plane PRELIMINARY

WAIT { 0, ticks[14:0] }       ticks more ticks elapse before the next record is consumed.
                              WAIT 0 is a no-op.  A WAIT n consumed at the boundary of tick k
                              lets ticks k .. k+n-1 play; the next record is consumed at k+n.
SET  { 1, addr[6:0], v[7:0] } voice RAM[addr] = v.  Takes no tick.  Any number execute at one
                              boundary until a WAIT or an empty FIFO, bounded by the idle gap.

Records are consumed only at tick boundaries, in the idle gap after the walk. At a boundary the WAIT count is decremented first; if it is then zero, records are consumed until a WAIT with a nonzero count. An empty FIFO changes nothing: the voices keep sounding. This is the property the SAMPLES path lacks (§6, AR1): a missed vblank holds the last notes rather than draining to silence. ENGINE writes the pair through its existing SPARE strobe (mask bit 3), so ENGINE is unchanged. Hardware implements WAIT as a 16-bit SRAM field at a private address, loaded as the complement and walked toward all-ones by the same adder that advances phases; the contract above does not depend on that.

The SRAM is never reset. Software must SET every voice it uses, including AMP 0 and CTL 0 for the ones it does not, and must SET the LFSR voice select before a noise voice sounds; a select naming an unplayed voice (15) disables the LFSR. Power-on contents are garbage by contract.

3.4 The tick — execution model PRELIMINARY

One AUDIO_TICK falling edge is one tick. In order:

StepWhat happensSYSCLK
1AUDCMD: WAIT counts down; if zero, records are consumed until a nonzero WAIT or an empty FIFO. SETs take effect in this tick’s walk.idle gap of the previous tick
2Pass 0: pop the L byte of SAMPLES (or 0) into the accumulator; for each voice in index order, PHASE += INC (byte-serial, PHASE_LO read first, one 8-bit adder used twice, carry kept), write PHASE back, then add its sample if PAN_L. Latch the left DAC.8 × 8 accesses × 3 + 2
3Pass 1: pop the R byte of SAMPLES (or 0); for each voice re-read PHASE_HI, CTL and AMP (or the table byte) and add its sample if PAN_R. Latch the right DAC.8 × 3 accesses × 3 + 2
4If the LFSR voice’s phase add carried this tick, shift the LFSR once. Every voice in both passes read the pre-shift value. (Model law; the LFSR did not fit rung ii, where MODES 1 and 3 play as square.)1

Voice sample by MODE: square is phase[15] ? +AMP : −AMP; noise is lfsr[0] ? +AMP : −AMP with the SN76489AN register, 15 bits, taps 0 and 1 fed back into bit 14 for white and the plain 15-bit ring for periodic; wavetable is SRAM[WAVE_PAGE × 256 + phase[15:8]], a signed byte already at its volume. Adds saturate to −128..+127 individually, so −(−128) clips rather than wraps. The two channels never interact, so the two-pass hardware is bit-identical to a model with two accumulators in one pass. RESET_PHASE zeroes PHASE when its SET executes and, on the LFSR voice, reseeds the register to 0x4000, which is the SN76489’s behaviour on a noise control write.

3.5 PSG driver — nine bytes a frame become a dozen SETs PRELIMINARY (model)

mixer/psg_driver consumes the same byte stream an SN76489 would and emits SETs only for voice bytes that changed. Tone period N maps to INC = round(3579545 / (32 N) × 65536 / 15734.375) from a 1024-entry table; attenuation maps to AMP from the 2 dB ladder at the chosen peak; noise control maps to the noise voice’s INC (rates 0x10/0x20/0x40, or tone 2’s period for rate 3), MODE 1 or 3, and RESET_PHASE. Periods 1..7 store INC mod 65536 for tones, which is the exact alias the chip itself produces, and 0xFFFF for noise. Measured over the whole Smurf playthrough: 0.93 SETs per field mean, 12 max, 17 on the first frame (the LFSR voice select rides first), and the death frame’s 61 emissions fit in 91 words.

3.6 Volume without a multiplier ADVANCE

A square or noise voice has exact phase-continuous volume for free: AMP is a byte the accumulator adds or subtracts. A wavetable voice gets volume by page selection, 16 pre-scaled copies of a 256-byte wave in 4 KB, so the 8K SRAM holds the voice records plus one such bank. Which is why noise as a 256-byte table and square as a table are also on offer if the LFSR does not fit: MODE 2 is the general mechanism and MODES 0/1/3 are the cheap special cases.

3.7 What the PSG subset cannot express PRELIMINARY (measured)

A 16-bit INC carries at most one carry per tick, so a noise voice shifts at most once per tick. The SN76489 at rate 3 clocked from tone 2 at period 4 shifts 1.8 times per sample; in Smurf’s jump tail (54 fields) periodic noise tops out at 1049 Hz where the chip reaches 1864 Hz. This is the only deviation the model cannot represent, and listening found it unobjectionable. Volume changes do not restart the wave (the run-record proposal’s weakness is gone). Nothing here plays FM.

Application Notes4

Costs are bus words per field (ENGINE delivery) and 68000 cycles per field. The frame budget reference is 233,625 SYSCLK per field.

PSG game port — three tones and noise, SN76489-class≤12 SETs + WAITs per field · a few hundred cyclesPRELIMINARY (model)

Recipe: voices 0..2 square, voice 3 noise, all PAN_L+PAN_R; the game’s PSG bytes go through psg_driver (§3.5) into a small record buffer; one descriptor per field points at it, followed by a WAIT to the next field boundary. Queue field k+1’s records during field k so the chain never re-syncs on an empty FIFO (AR3).

Notes: the Smurf port. Pitch within 2 cents everywhere, ladder within 0.5 LSB, invariants hold every tick; A/B judged equal or better than the software reference on 2026-09-26.

PCM soundtrack or one-shots — the rev-1 path263 words/field per stereo stream · CPU renders or copies the samplesPRODUCTION (rev 1)

Recipe: a sample buffer in RAM; the display list deposits it in bursts of at most 32 words spread across the field (Smurf: 9 bursts) so the 256-pair FIFO never underruns and never overflows. Under MIXER it mixes beneath the voices automatically.

Notes: a field is 262.5 pairs and the FIFO holds 256, so one missed vblank empties it and the DAC holds (AR1). Rev 1 apps re-prime after a miss; MIXER-era apps can leave PCM idle and rely on voices instead.

Tracker / chiptune playback — song as a record list≈3–20 words per row · zero cycles while playingADVANCE

Recipe: a whole song is SET/WAIT words in RAM; ENGINE streams it with count-32 descriptors as the FIFO drains. WAIT counts are tick-exact and raster-locked, so tempo never drifts against the picture. Envelopes are AMP SETs at chosen ticks; arpeggios are INC SETs.

Notes: the 256-word FIFO holds seconds of sparse music; the app only has to keep it non-empty. Fifteen voices need more idle gap than eight; check the SET bound (§6, AR4).

Wavetable instruments and drums4 KB SRAM per instrument at 16 volumes · loaded by SETs onceADVANCE

Recipe: load 256-byte tables through SETs is not possible (SETs reach only the 7-bit window), so tables are loaded through a MIXER control mechanism still to be specified, or preloaded; a MODE 2 voice then plays any single-cycle wave, and a one-shot drum is a table played once by an INC chosen so the phase wraps at the sample’s end followed by AMP 0.

Notes: the table-load path is the open specification item for this mode. Until rung (ii) fits the table read, this is concept only.

Stereo effects over musicone PAN bit per voicePRELIMINARY

Recipe: music voices PAN_L+PAN_R; a sound effect on a spare voice with PAN_L or PAN_R only, or a PCM one-shot with the other channel’s byte at 0.

Notes: amplitude budgeting is the driver’s job: with eight voices at a peak of 31 the sum can reach 248 and will saturate; keep the sum of active peaks under 127 per channel unless clipping is wanted.

Speech and sampled sound on a voice≈16 SETs per 256 samples at PCM ratesADVANCE

Recipe: not this way. A voice plays a 256-byte loop; long samples belong on the SAMPLES stream, which costs nothing but bus words and mixes under the voices for free.

SRAM and Read-Port Timing5

The walk assumes three SYSCLK (214 ns) per SRAM read and, after the step-3 datasheet check, four per write: address registered at the edge that starts the access; /OE low for the middle two clocks (135 ns worst); read data captured at the edge that ends the access; on a write, /WE low for t1–t2 only and address and data held through t3 so the address outlasts /WE’s rise by a full clock; one dead clock on the byte bus at every read/write turnaround. A 7200 read on the shared bus holds /R low for two clocks and captures at the end. The DAC byte is stable one clock either side of a one-clock latch pulse. Every number below is from a table fetched on 2026-09-26 (griffin.log, step 3 entry); the chosen SRAM is the MCM60L64P10, because no table exists for the KM6264L-15 grade and the KM6264A generation needs 5 ns of address hold after write that a same-edge /WE cannot give.

Authoring Rules and Limitations6

6.1 Rules of thumb for a sound driver PRELIMINARY (model)

#Rule of thumb
RT1Silence is not free at power-on. The SRAM starts as garbage. Before the first note, SET AMP 0 and CTL 0 on every voice you do not own, and SET the LFSR voice select.
RT2A note is one descriptor. Three words, SET INC_LO, SET INC_HI, SET AMP, delivered by ENGINE from RAM; you never write a register. Only send bytes that changed.
RT3WAIT is the clock; queue a field ahead. A WAIT that expires on an empty FIFO re-syncs to whenever the next words arrive, so deliver field k+1’s records during field k and the timing stays tick-exact.
RT4Missed vblanks hold, they do not silence. Voices keep sounding on an empty AUDCMD FIFO; only the PCM stream drains. Design so that a held note is the failure mode, not a dropout.
RT5Budget amplitude, not the chip. Saturation happens on every add. Keep the sum of active peaks under 127 per channel; at a per-voice peak of 31 that is four voices, at 15 it is eight.
RT6Pitch is exact enough; do not table-correct it. The 16-bit increment lands every PSG period within 2 cents. Sweeps update INC once per field or once per row.
RT7Long samples go on SAMPLES, short waves go in tables. A voice plays 256 bytes; anything longer is PCM through the other stream and mixes under the voices for nothing.

6.2 Rules and limitations PRELIMINARY

#Rule
AR1SAMPLES holds 256 pairs and a field consumes 262.5; a full-rate PCM stream must receive at least two deposits per field, spread so the level never crosses 0 or 256 (rev 1 measured: one miss = two fields of held DAC).
AR2AUDCMD words go to the pair only through ENGINE’s SPARE strobe; a write to a full FIFO is lost. Keep the queued record count under 256 by construction (a field of Smurf is at most 91).
AR3SETs at one boundary are bounded by the idle gap: 53 with eight square voices, 49 with eight table voices (measured, rung ii); records beyond the bound execute at the next boundary, and a record already started completes first. The model carries the bound as a checked constant.
AR4SETs in one boundary execute in queue order and before the walk, so a PHASE SET after RESET_PHASE wins and a SET is heard in the same tick.
AR5One LFSR per chip in the model; which voice steps it is control byte 0x78, and a shift is heard one tick after the carry. The rung ii chip has no LFSR: noise is a MODE 2 table (periodic noise exact, white noise approximated).
AR6A noise voice shifts at most once per tick; an SN76489 rate-3 noise clocked above the tick rate is clamped (§3.7).
AR7The left DAC latches about 7 µs before the right. Treat the pair as one sample; nothing an application does can observe the skew.
AR8Nothing in the SRAM is reset by /RS; /RS clears the WAIT field and empties both FIFOs. Voice state survives a reset and must be re-established by software (RT1). RESET_PHASE is stored and ignored in rung ii; two SETs of PHASE 0 do the same.
AR9Tables are outside the SET window; MODE 2 depends on a table-load path not yet specified. Until it is, MODE 2 is a fit rung, not an application mode.
