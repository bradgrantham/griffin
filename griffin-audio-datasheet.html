Features

  • Stereo 8-bit two’s complement output at 15,734.375 Hz, tick-locked to the raster (262.5 ticks per field)
  • One 16-bit record stream from ENGINE DMA carries voice SETs, WAITs, inline PCM, table descriptors and program uploads
  • Voices with 16-bit phase, signed 8-bit amplitude, L/R pan; square, wavetable and SN76489-style LFSR noise
  • Tables and the PCM ring live in the Z80’s own RAM: the same machine is stereo PCM or many wavetables, by what the 68000 loads
  • A title may upload its own sound program and run it (exact PSG emulation at the register-write level)
  • Phase-continuous volume; a missed vblank holds the notes, it never silences them
  • No 68000-visible registers, no status path: deposits are scheduled against documented drain rates

Device Complement

  • ENGINE — existing descriptor DMA master; AUDIO_FIFO_W strobe, unchanged
  • 2× IDT7200L15 — the rev-1 audio pair footprint, now one ganged 16-bit record FIFO; a 7201 (512 deep) drops in
  • Z80B 6 MHz on its own 6.000 MHz can; 27C128 program + tables; 6264 8K×8 RAM
  • 74HC138 + half a 74HC139 decode; 4.7 k pull-up pack on the Z80 data bus
  • 2× 74HC574 DAC latches driving the existing R-2R ladders, LM358 stage, 3× LM386 (rev-1 CD4049 inverters removed)
  • 12-pin debug header: /WR, /IORQ, DEBUG select, D0..D7, GND
  • PORTS — rev-1 pop logic (AUDIO_CONTROL / AUDIO_STATUS) retires (package B)

Proposal revision. Rev 1 ships the SAMPLES path only (§3.1 rev 1): ENGINE fills a FIFO pair and PORTS pops it to the DACs. Everything else on this page is the Z80 sound processor decided on 2026-09-26 after the CPLD form (§7, retired row) fitted with no headroom. The tick law is the shared model that passed its A/B against the SN76489 recording; the Z80 program is being measured against that model bit for bit (§5). Nothing here has run on hardware, and rev-1 boards cannot take it. PRELIMINARY marks what the model pins and the Z80 test is confirming; ADVANCE marks concepts; OPEN marks a question no gate has answered.

General Description1

The audio pipeline keeps the video pipeline’s shape, one stream in and a stateless consumer, but puts the consumer in software: a small Z80 with its own ROM and RAM reads a FIFO of 16-bit records that ENGINE deposits by DMA, and produces one stereo sample pair per AUDIO_TICK. Records are voice writes, waits measured in ticks, inline PCM, table descriptors, and program uploads. All voice state, every wave table and the PCM ring live in the Z80’s RAM, so the 68000 decides what the machine is by what it loads. The CPU never touches a sound register; it writes records into RAM and points a descriptor at them, exactly as it does for VIDCMD.

Mechanisms3

Status stamps: PRODUCTION = built, verified; on rev-1 boards for the rev-1 SAMPLES path. PRELIMINARY = law pinned in mixer/mixer.h and griffin.yml, Z80 program under measurement. ADVANCE = concept, specification may change.

3.1 The record stream — one FIFO, everything in band PRELIMINARY

ENGINE deposits one 16-bit word per AUDIO_FIFO_W strobe into the ganged pair, at most 32 words per descriptor, from anywhere in RAM. The Z80 reads the high byte (port 0xFF) then the low byte. A high byte of 0xFF means the FIFO was empty and nothing was popped. Deposits are placed at lines in the display list; the author keeps the queue inside the FIFO’s depth against the drain rates of §5, because a write to a full 7200 is ignored. Rev 1 PRODUCTION: the same pair holds {L, R} sample words, PORTS pops both chips on every tick while AUDIO_CONTROL.ENABLE is set, and AUDIO_STATUS.EMPTY is the raw /EF; that path stays in griffin.yml as rev-1-only until package B.

3.2 Records PRELIMINARY

1aaa aaaa vvvv vvvv   SET      RAM[window + a] = v.  No tick.  a = 0x7F reserved (0xFF = empty).
00tt tttt tttt tttt   WAIT     t ticks (max 16383 = 1.04 s).  WAIT 0 is a no-op.  A WAIT n consumed at
                               the boundary of tick k lets ticks k .. k+n-1 play; next record at k+n.
0100 0000 rnnn nnnn   SAMPLES  n {L, R} words follow (n <= 127); r = play each pair twice (7.8 kHz).
                               Copied into the SRAM ring, a bounded number of pairs per tick.
0100 0001 nnnn nnnn   LOAD     word: destination; n words; word: 16-bit sum.  Bad sum = image marked invalid.
0100 0010 ---- ----   JUMP     word: entry.  Refused after a bad LOAD.  The ROM keeps the NMI entry.
0100 0011 vvvv vvvv   VOICE    v: two words follow, table base and table length (power of two).
0100 0100 ---- ----   RESET    ROM synth state: every voice silent, ring empty, DACs at midscale.

Records are consumed in the idle gap between ticks, in order, so SETs queued before a boundary take effect in that tick’s mix. An empty FIFO changes nothing: the voices keep sounding. Constants: AUDIO_REC_* in griffin.yml; helpers in sound/audio_records.h.

RAM is never reset by /RS. Software SETs every voice it uses and silences the rest (AMP 0, CTL 0) or sends RESET; the LFSR voice select must be SET before a noise voice sounds.

3.4 The tick — execution model and the ROM-owned NMI PRELIMINARY

StepWhat happens
gapMain loop: read the FIFO; execute SETs, load WAITs, copy SAMPLES pairs into the ring up to the per-tick cap, LOAD/JUMP/VOICE/RESET. Records beyond the gap wait for the next gap.
NMIROM entry at 0x0066: save registers, re-seed SP, note re-entry (overrun), call the tick vector in RAM.
tick 1WAIT counts down; pop one ring pair (or 0) as the L and R seeds.
tick 2Each voice in index order: PHASE += INC; sample by MODE (square: sign of phase; wavetable: table[base + phase >> (16 − log2 length)]; noise: LFSR bit); ±AMP or the table byte into each PAN-enabled accumulator, saturating on every add.
tick 3OUT both accumulators with bit 7 inverted; shift the LFSR once if the LFSR voice’s add carried.
epilogueRestore, RETN. Three consecutive overruns swap the tick vector back to the ROM synth.

This is Mixer::tick() of mixer/mixer.h, the model that passed the SN76489 A/B, and the Z80 program is compared to it bit for bit. The LFSR is the SN76489AN’s: 15 bits, taps 0 and 1 into bit 14 for white, the plain ring for periodic; every voice in a tick reads one value and a shift is heard one tick after the carry. −(−128) clips.

3.5 PSG driver — nine bytes a frame become a dozen SETs PRELIMINARY (model)

mixer/psg_driver consumes the same byte stream an SN76489 would and emits SETs for voice bytes that changed: period to INC through a 1024-entry table, attenuation to AMP through the 2 dB ladder, noise control to the noise voice’s INC, MODE and RESET_PHASE, the LFSR select first. Over the Smurf playthrough: 0.93 SETs per field mean, 12 max, 17 on the first frame; the 61-emission death frame is 91 words. Periods 1..7 store INC mod 65536 for tones, the chip’s own alias.

3.6 Uploaded programs — a title brings its own chip ADVANCE

LOAD places bytes anywhere in RAM with a 16-bit sum; JUMP hands the tick vector, or the whole main loop, to the image. The NMI vector stays in ROM, so the ROM’s entry still runs first and still recovers. An uploaded SN76489 or AY-3-8910 at the register-write level makes the 68000 side of a port a byte forwarder: SET carries the chip’s own register write and the Z80 does the mapping. By napkin, an SN76489 (three tones and noise) costs about 400 T per tick and an AY about 450; both fit 6 MHz once the feasibility numbers of §5 confirm the per-voice cost. FM chips do not fit at any bin clock.

3.7 Limits PRELIMINARY (measured on the model)

A 16-bit INC gives at most one LFSR shift per tick; the SN76489 reaches 1.8 per sample at rate 3 clocked from tone 2 at period 4, so in Smurf’s jump tail periodic noise tops out at 1049 Hz where the chip reaches 1864 Hz (54 fields). Listening found it unobjectionable. Voice count and PCM trade against each other inside 381 T per tick.

Application Notes4

Costs are bus words per field (ENGINE delivery) and 68000 cycles per field. The frame budget reference is 233,625 SYSCLK per field.

PSG game port — three tones and noise, SN76489-class≤12 SETs + WAITs per field · a few hundred cyclesPRELIMINARY (model)

Recipe: voices 0..2 square, voice 3 noise, all PAN_L+PAN_R; the game’s PSG bytes go through psg_driver (§3.5) into a record buffer; one descriptor per field points at it, followed by a WAIT to the next field boundary. Queue field k+1’s records during field k so the chain never re-syncs on an empty FIFO (AR3).

Notes: the Smurf port. Or, once uploads exist, forward the raw PSG bytes to an uploaded chip emulation (§3.6).

PCM soundtrack or one-shots — SAMPLES records into the ring≈270 words/field per stereo stream · CPU copies or renders the samplesPRELIMINARY

Recipe: a sample buffer in RAM; the display list deposits SAMPLES 32 chunks spread across the field (Smurf’s nine bursts already have this shape). The ring holds fifteen fields, so the 68000 may run seconds ahead and a missed vblank costs nothing.

Notes: a SET queued behind a 32-pair chunk waits until the chunk has been copied, under a millisecond; keep chunks at 32 (§6, AR2). Half rate (r = 1) halves the words for speech.

Tracker / chiptune playback — song as a record list≈3–20 words per row · zero cycles while playingADVANCE

Recipe: a whole song is SET/WAIT words in RAM; ENGINE streams it with count-32 descriptors as the FIFO drains. WAIT counts are tick-exact and raster-locked. Envelopes are AMP SETs at chosen ticks; arpeggios are INC SETs.

Wavetable instruments and drums — VOICE + LOADa table is LOAD words once; a note is 3 SETsADVANCE

Recipe: LOAD a single-cycle wave or a drum hit anywhere in Z80 RAM; VOICE names its base and length for a voice; a one-shot is an INC chosen so the phase runs the table once, followed by AMP 0. Volume by AMP for square and noise voices; for table voices by choosing among pre-scaled copies, or by an uploaded program that multiplies.

Stereo effects over musicone PAN bit per voicePRELIMINARY

Recipe: music voices PAN_L+PAN_R; an effect on a spare voice with PAN_L or PAN_R only, or a SAMPLES one-shot with the other channel’s byte at 0.

Notes: amplitude budgeting is the driver’s job: keep the sum of active peaks under 127 per channel unless clipping is wanted.

Z80 Budget and Drain Rates5

The tick is 381.3 T at 6 MHz. Everything the ROM does per tick and per record is counted by hand from the Z80 timing tables first and then measured on the z80emu harness against the recorded Smurf stream (sound/README.md). Authoring Rules and Limitations6

6.1 Rules of thumb for a sound driver PRELIMINARY (model)

#Rule of thumb
RT1Start with RESET, then SET what you own. RAM is not reset. RESET silences every voice and empties the ring; then SET the LFSR voice select and your voices.
RT2A note is one descriptor. Three words, SET INC_LO, SET INC_HI, SET AMP, delivered by ENGINE from RAM; you never write a register. Only send bytes that changed.
RT3WAIT is the clock; queue a field ahead. A WAIT that expires on an empty FIFO re-syncs to whenever the next words arrive, so deliver field k+1’s records during field k.
RT4Schedule, don’t poll. There is no readback. Place deposits at lines so the queue never exceeds the FIFO’s depth against the §5 drain rates; the ring absorbs PCM, the FIFO only has to absorb what arrives between two gaps.
RT5Budget amplitude, not the chip. Saturation happens on every add. Keep the sum of active peaks under 127 per channel; at a per-voice peak of 31 that is four voices.
RT6Pitch is exact enough; do not table-correct it. Every PSG period lands within 2 cents. Sweeps update INC once per field or once per row.
RT7Long samples go through SAMPLES, short waves through VOICE. A table voice loops; anything longer than the table streams through the ring and mixes under the voices.

6.2 Rules and limitations PRELIMINARY

#Rule
AR1Records go to the FIFO only through ENGINE’s AUDIO_FIFO_W strobe; a write to a full 7200 is ignored. The author keeps the queue inside 256 (512 with a 7201) by construction.
AR2A SAMPLES chunk is copied a bounded number of pairs per tick, so a record behind it waits chunk length divided by that rate. Keep chunks at 32 pairs: under a millisecond of latency for the record behind.
AR3Records execute in the idle gap, in order, before the next tick’s mix; how many fit in one gap is the §5 drain rate. Records beyond it execute next gap.
AR4SETs execute in queue order, so a later PHASE SET wins over RESET_PHASE, and a SET queued before a boundary is heard in that tick.
AR5One LFSR; which voice steps it is control byte 0x78; other noise voices read the same register; a shift is heard one tick after the carry.
AR6A noise voice shifts at most once per tick (§3.7).
AR7Nothing in RAM is reset by /RS; the ROM initialises its own state and parks the DACs at midscale. Uploaded programs are gone after a reset and must be LOADed again.
AR8SET reaches only the 128-byte window. Tables and programs enter through LOAD; VOICE tells a voice where its table is. SET address 0x7F is illegal.
AR9A JUMP after a LOAD whose sum failed is refused; the NMI entry always belongs to the ROM, and three consecutive overruns return the tick to the ROM synth.
AR10Nothing on the 68000 side observes the Z80. Bring-up and debugging use the header and a probe; the steady state assumes it works.
